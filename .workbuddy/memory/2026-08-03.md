## 本次修复（动态壁纸 bug 收尾）

用户新诊断暴露两个叠加问题：

1. **测试窗口崩溃（品红不显示的直接原因）**
   - `EntryPointNotFoundException: FillRect in gdi32.dll` —— 渲染进程第一次 WM_PAINT 抛异常挂掉。
   - 改用 `PatBlt` + `SelectObject`（gdi32 稳定导出）。`NativeMethods` 删 FillRect，加 SelectObject/PatBlt/PATCOPY。
   - `WallpaperChildWindow.WndProc` 改为 SelectObject(brush) → PatBlt(PATCOPY) → 还原。

2. **查找逻辑要求 WorkerW 可见（导致每次回退 Progman）**
   - 真正的壁纸 WorkerW 在桌面最底层，`IsWindowVisible` 返回 false，被旧逻辑过滤掉。
   - `WorkerWHost` 重写 `TryResolve`：从 Progman 沿 GW_HWNDPREV 向下扫第一个满屏(≥50%虚拟屏)、不含 DefView 的 WorkerW（不要求可见）。
   - 新增第二条路径：Win11 26200 上壁纸 WorkerW 可能是 **Progman 的子窗口**，故也扫 Progman 的 WorkerW 子窗口。
   - 删除旧 FindExistingUsable/WaitForNewWorkerW/FindDefViewHolder/IsUsableSurface/SnapshotWorkerW/EnumerateTopLevel。
   - `DumpShellTopology` 改为打印从 Progman 向下的 z-order 链，便于定位。
   - `PreviewStrategy` 改用 TryResolve。

3. **诊断增强**：`WallpaperDiagnostics` 现在额外打印 Progman 的子窗口列表 + 从 Progman 向下的 z-order 链，用于确认壁纸层结构（顶层 vs Progman 子窗口）。

## 新增功能（设置持久化 + 渲染进程脱离 GUI）
- 用户诉求：关掉 DesktopSuite.exe 后动态壁纸消失，希望保留，且"下次打开记住上次设置"。
- 根因：原架构给渲染子进程挂了 Job Object + `KILL_ON_JOB_CLOSE`；GUI 退出→Job 关闭→mpv 渲染进程被一起杀掉。
- 方案 1（脱离 GUI 生命周期）：`WallpaperEngine` 不再把渲染进程放进 Job Object（删除 `CreateRendererJob`/`AssignProcessToJobObject` 调用及相关 `_rendererJob` 字段、using）。`Dispose()` 改为**不再 StopDynamic**，只释放 WorkerW 句柄 → 渲染进程独立存活，关 GUI 壁纸仍在。
- 方案 2（轻量设置存储）：新增 `AppSettings.cs`，用 `System.Text.Json` 存到 `%LocalAppData%/DesktopSuite/settings.json`。字段：`AudioEnabled`、`Volume`(默认80)、`LastMedia`、`RendererPid`。
- 接管机制：`WallpaperEngine` 新增 `Adopt(int pid)`（重启 GUI 后按保存的 PID 重新接管仍在跑的渲染进程，带进程名 "DesktopSuite" 防 PID 复用误接管）与 `StopByPid(int pid)`（按 PID 杀旧渲染进程，同样带进程名防护）。
- UI 接线：`MainWindow` 构造时 `AppSettings.Load()` → 回填 ChkAudio/VolSlider/VolLabel → `_wallpaper.Adopt(_settings.RendererPid)` → 刷新状态；`BtnStartDynamic` 前先 `StopByPid` 防重复，启动后写回并 `Save()`；`ChkAudio` 勾选变化与 `VolSlider` 拖动均更新 `_settings`（落盘在 start/stop/close）；`OnClosed` 先 `Save()` 再 `Dispose()`（**不杀渲染进程**）；`BtnStopDynamic` 清 `RendererPid=0` 并保存。
- 设计决策：重启 GUI **不自动重新播放**壁纸（避免无声启动 mpv 的惊喜）；而是渲染进程本就一直在跑，GUI 只是检测并接管它。测试图案(StartTestPattern)不改、不持久化。
- 选择 JSON 而非注册表：跨用户目录、可读、无权限/污染问题；注册表作为备选未采用。
- 构建：`dotnet build -c Debug` 0 警告 0 错误。
