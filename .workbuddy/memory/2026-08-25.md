## v21 修复：FrostOpacity 极低时毛玻璃变白
- **根因**：`_frostBmp` 是 BoxBlur 输出的 **alpha=255（不透明）** 模糊图；当 FrostOpacity 极低（0~14）时，
  `FillRoundedRectWithAlpha` 叠加的暗色太淡 → alpha=255 的亮色模糊底色几乎无染色 → 视觉上呈白色/灰白。
  若 `_frostBmp` 捕获失败为 null，frosted 分支整个跳过且无 else-branch → body 区域无填充 → 也可能异常。
- **改动**：
  - DrawBoxes frosted 分支：FrostOpacity 渲染时 `Math.Max(值, 20)` 最小 20（约 8%，确保模糊效果始终可见）。
  - 新增 `else if (_appearance.Frosted)` 分支：_frostBmp 为 null 时 fallback 到普通半透明 body fill（防白屏）。
- 编译 0 错误；发布 ds2（exe Aug 25 23:56）。提交 + 双远程推送 v21（待 commit/push）。
- **待用户真机复验**：FrostOpacity 拉到 0~20 区间不再变白、保持模糊可见；换壁纸刷新（v20+ v21 一并验）。

### v22 根因定位（决定性证据 = 图3 不一致性）
- 同一张 `_frostBmp`（全窗口一次截屏+模糊），部分盒子正确部分白色 → **问题在捕获内容而非渲染**
- **真正根因：`EnsureFrostCapture` 的 `CopyFromScreen` 捕获到自己窗口的上一帧（自捕获反馈循环）**
  - `CopyFromScreen` 截取的是屏幕合成输出（包含我们自己的 layered window）
  - 低 FrostOpacity → 上一帧亮 → 捕获亮 → 本帧更亮 → 死锁在白色
  - 高 FrostOpacity → 上一帧暗 → 捕获暗 → 再加 162 暗色染色 → 暗到看不见模糊
  - 图3 不一致性：不同盒子区域在上一帧亮度不同（BodyOpacity/图标密度差异）
- **v21 的 Math.Max(frostA,20) 没有解决根本问题**——它只增加染色强度，但 _frostBmp 内容本身就是错的
- **v18"正常"的原因**：用户测试时用中等 FrostOpacity（暗色掩盖了自捕获痕迹），且只是随手开关确认未测极端值
