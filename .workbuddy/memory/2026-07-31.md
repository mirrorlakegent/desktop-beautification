# 2026-07-31

## Windows 桌面美化套件 · 全流程技术方案（GStack 五人团队协作）

用户需求：封装 EXE，实现壁纸（静态+动态）、主题、小组件、Dock、桌面整理、AI 设计六大模块。定位个人自用。

### 已确认的关键决策（用户拍板）
- **技术栈：C# .NET 8/9 + WPF（核心）+ WebView2（渲染层）+ mpv.exe（外挂硬解）**
  - 用户自评「Rust 和 C# 都不熟，要最快出成果」→ 选 C#
  - 明确是 WPF 不是 WinUI3（WinUI3 非打包部署会让单 EXE 目标很难受）
- **动态壁纸走集成 Lively Wallpaper 路线，不自研 WorkerW 注入**
- **砍掉 Windows 系统主题改造**（需求第 2 条），保留 theme.json 应用内主题体系
- MVP 四块：壁纸引擎、桌面整理+图标隐藏、Dock、小组件

### 架构铁律（团队产出，不可动摇）
1. 桌面整理**锁死虚拟视图，一个文件都不动** —— Win11 默认把桌面重定向进 OneDrive，移动真实文件 = 后端删除+新建，删除会同步到其他设备
2. 桌面整理用「隐藏 DefView + 自绘图标层」，**绝不跨进程操作 SysListView32**（需 VirtualAllocEx 写 explorer 内存，杀软必报）
3. **三进程隔离**：主程序 / 壁纸渲染器 / 小组件宿主，必须选型阶段定死
4. **全程不提权，无 admin manifest**
5. AppBar **默认不注册** —— 「进程被杀后屏幕边缘永久留白」的失败模式整个消失
6. 小组件用**单个全屏透明窗口 + 单 WebView2** 承载全部组件，不是 N 个实例（每个 40-80MB）
7. WebView2 直接 `IsScriptEnabled = false`
8. 所有 HWND 一律不缓存，注册 `TaskbarCreated` 广播后全模块重建
9. 多显示器配置持久化用 `GetMonitorDevicePathAt` 设备路径，**不用索引**

### 重要技术事实
- **.NET 8/9 官方不支持 WPF 裁剪**（XAML/BAML 动态类型解析），强开 PublishTrimmed 会运行时 XamlParseException。减体积只能靠压缩 + InvariantGlobalization（省 28MB ICU）
- **自签名证书对 SmartScreen 完全无效**（只认证书累积信誉）。本地自编译产物无 MOTW，压根不弹 → 不要买证书
- **对比度死区**：底色 OKLCh 明度 L ∈ [0.58, 0.82] 时黑白文字都够不到正文门槛 Lc 75，最劣点 L=0.72 上限仅 55。落进死区时调文字色无效，必须回面板层加不透明度。死区是一条带不是阈值，色阶要逐档校验
- **AI 不应输出完整 theme.json**（200+ 字段 + 需数学推导的派生值）→ 三段式：ThemeIntent（~35 字段/28 枚举）→ 确定性 Expander → Validator
- **架构红利**：因虚拟视图 + ShowWindow 隐藏而非改注册表/移动文件，最坏情况破坏全是非持久化的，explorer 一重启必然恢复 —— **不存在「重启也回不去」的状态**
- 情报甄别：中文技术站大量「Win11 24H2 废掉 WorkerW」的文章是 AI 生成内容农场（含伪造数据表和虚构微软工程师发言）。以 Lively issue #2777 交叉验证，真实结论是注入仍可行但脆弱
