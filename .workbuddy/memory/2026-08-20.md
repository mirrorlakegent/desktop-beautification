# 2026-08-20 工作日志

## M4-B v10 透明度=0 白色 bug 修复（302e01c）
- **根因**：GDI+ `SolidBrush(Color.FromArgb(0, r, g, b))` 的已知怪癖——alpha=0 时不渲染为完全透明，
  而是显示为白色/不透明；叠加 `PremultiplyAlpha` 中 alpha=0 像素 RGB 未清零
- **修复**：
  1. `DrawBoxes`：BodyOpacity/HeaderOpacity/FrostOpacity ≤ 3 时**跳过填充**，让 `Clear(transparent)` 自然透出壁纸
  2. `PremultiplyAlpha`：alpha=0 分支显式清零 R/G/B
- 编译 0 错误，发布 ds2，双远程推送成功（2d4ef62..302e01c）
- 待用户重启复验：拖动主体透明度到 0 → 围栏应完全透明（透出壁纸），不再变白

## M4-B v11 透明度变白（再修，fb668bb）
- **用户重启 ds2 后仍反馈"没有改善"**——v10 只处理了 alpha=0 极端值，但 `SetAppearance` 的
  clamp 把滑块 0 钳到 40，而 **40 恰好落在 GDI+ 低 alpha 异常区间**（<~60 时暗色填充被渲染为
  浅灰/白）。需从根因重新分析。
- **完整根因（6 个叠加）**：
  1. （主因）GDI+ `SolidBrush` 低 alpha(<~60) 在 Format32bppArgb 上渲染异常 → 暗色变白
  2. clamp 下限 40/80 阻止真正透明，且把滑块 0 强推入异常区间
  3. 边框无条件 alpha=160，低透明度时成主视觉（硬性空框）
  4. 标题栏最低 80（31%）
  5. 图标文字 alpha=235（92% 浅灰）
  6. 标题文字 alpha=255（全白）
  → 滑块拉低时：GDI+ 失真 + 边框/文字凸显 = 白色方块；默认 180 远离异常区间故正常
- **修复**：
  1. 移除 `AppSettings.Load()` 与 `FenceLayer.SetAppearance()` 的 Body/Header clamp 下限 → 允许真正透明(0)
  2. 主体+标题栏填充改用 **ColorMatrix 方案**（绕过 GDI+ 低 alpha Brush）：
     全不透明画圆角/标题形状到缓存临时位图 → `SetColorMatrix` 整体缩放 alpha → `DrawImage` 合成；
     临时位图 `_alphaFillTmp` 复用（按最大盒子尺寸增长），避免频繁分配；毛玻璃着色同样走此路径
  3. 边框 alpha 随 BodyOpacity 线性缩放 `min(160, Opacity*160/180)`，低透明度时边框同步淡出
- 提取 `HeaderPath(x,y,w,h,r)` 复用；`FillRoundedRectWithAlpha`/`FillHeaderWithAlpha`/`EnsureAlphaTmp`/`DrawTmpWithAlpha` 新增
- 编译 0 错误（1 个无关旧 warning），发布 ds2，双远程推送（302e01c..fb668bb）
- 待用户重启 ds2 复验：滑块 0→完全透明、滑块 40-180 渐变暗、全程不再变白
- **关键经验**：GDI+ 低 alpha SolidBrush 在 32bppARGB 不可信；需要可控半透明时一律用
  ColorMatrix(alpha 缩放) + DrawImage，且不要对 UI 透明度设人为下限（clamp 反而制造 bug）
