## M4-B v12b: ApplyBodyAlpha 竞态条件修复（3f45ab8）
- **用户重启 v12 后仍反馈 4 张截图：透明度=0 时全部白色（含空围栏"临时"），137/195/255 正常**
- **v12 失败根因**：`ApplyBodyAlpha(bmp)` 被放在 `using (var g = Graphics.FromImage(bmp))` 块**内部**
  调用。GDI+ 将部分渲染操作（文字抗锯齿清理、内部缓存刷新）延迟到 `Graphics.Dispose()` 才
  执行。LockBits 在 GDI+ 仍持有位图时操作像素 → 我们的 alpha 修改被 GDI+ 延迟写入覆盖
- **修复**：将 `ApplyBodyAlpha(bmp)` 移到 using 块外部，确保 Graphics 完全 Dispose 后再执行
- 编译 0 错误，发布 ds2，双远程推送（42361bd..3f45ab8）
- 待用户重启复验

## M4-B v13: LockBits 像素填充彻底重做（c82d91f）
- **用户反馈 v12b 仍变白 + 图标也被压成半透明**（v12 ApplyBodyAlpha 把主体区域发展所有像素含图标一起缩放 alpha）
- **v13 方案**：重构渲染顺序 —— 先 `FillBodyPixels`（LockBits 直接写主体背景 ARGB 精确值，彻底绕过 GDI+ 低 alpha Brush 缺陷），之后 GDI+ 仅在背景之上绘标题/边框/图标/文字（保留各自 alpha，图标不再被压暗）。
  - BodyOpacity=0 → FillBodyPixels 直接 return，主体像素保持透明（透壁纸）
  - BodyOpacity>0 → 写 (A=opacity,20,22,28)，末尾 PremultiplyAlpha 统一预乘
  - 删除 ApplyBodyAlpha（含「图标半透明」副作用）
- 发布受阻于 VS Code 扩展锁 obj → 用 `rm -rf obj obj_v13` + 同会话 publish 解决（注意 `BaseIntermediateOutputPath` 须带尾斜杠，否则解析错）
- 编译 0 错误，发布 ds2，双远程推送（3f45ab8..c82d91f）
- 待用户重启 ds2 复验：拖主体透明度到 0 → 围栏完全透明、图标清晰可见

## M4-B v14: alpha=1 替代 alpha=0 绕过 GetHbitmap 缺陷（66d9daf）
- **用户反馈 v13 仍没有真正透明**（围栏从纯白变为浅灰白，但远非透明）
- **真正的根因**：不在 GDI+ 填充，而在管线末端 `.NET Bitmap.GetHbitmap()`：
  - GetHbitmap() 将 32bppARGB 转为 GDI DIB，BITMAPINFOHEADER 无 alpha 字段
  - alpha=0 像素在 DIB 中为"未定义" → UpdateLayeredWindow(AC_SRC_ALPHA) 渲染为白色
  - alpha>0 像素正常（完美解释为何仅透明度=0 失败、137/255 正常）
- **修复**：
  - FillBodyPixels: bodyA<=0 时写 alpha=1（0.4% 不透明度，人眼不可见但非零）而非 return
  - 新增 ClearBodyPixels(Bitmap): Graphics.Dispose() 后 LockBits 强制主体像素为 (0,0,0,1)，
    覆盖 GDI+ 泄漏（文字抗锯齿、边框等残留）
- 编译 0 错误，发布 ds2，双远程推送（c82d91f..66d9daf）
- 待用户重启复验：透明度=0 → 围栏应真正透明（或极淡 0.4% 残影）
