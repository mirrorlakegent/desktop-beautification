## v25d 毛玻璃（提交 2c3aa09，待真机复验）—— 换路线，绕开截屏
- **决策依据**：v21→v25c 六轮截屏方案受困同一死结——窗口是桌面 WorkerW 子窗口，
  CopyFromScreen 要么捕到自己的上一帧（SW_HIDE / ULW 透明帧 / SW_MINIMIZE 都清不掉 DWM 缓存），
  要么捕到移屏后暴露区域的 DWM 残留。
- **新方案**：新增 `LoadWallpaperFrost()`，用 `IDesktopWallpaper` COM（项目已有该接口）
  直接读壁纸文件路径，按 `DESKTOP_WALLPAPER_POSITION`（FILL/FIT/STRETCH/CENTER/TILE）换算缩放，
  映射窗口在虚拟屏幕中的位置裁剪对应区域，再做三重盒式模糊。
- **优点**：无窗口操作、无 DWM、无时序竞争、无反馈循环，背景即用户所选图片。
- **取舍**：不含桌面图标——对毛玻璃观感更贴合真实（真实毛玻璃模糊背景本身，非其上的物体）。
- 截屏路径保留为读取失败时的安全网（fallback）。
- 新增虚拟屏幕常量 SM_XVIRTUALSCREEN(76)/SM_YVIRTUALSCREEN(77)/SM_CXVIRTUALSCREEN(78)/SM_CYVIRTUALSCREEN(79)。
- 壁纸更换刷新链路已确认完整：`WM_SETTINGCHANGE` → `PostMessage(WM_FROST_REFRESH)`
  → `InvalidateFrost() + UpdateVisual()` → 重新从新壁纸文件加载。
- 发布 ds2（exe Aug 30 09:33），双远程已推（2c3aa09，已 ls-remote 验证同步）。

## v25e 毛玻璃（提交 d4766b2，待真机复验）—— 用 DesktopSuite 自身壁纸
- **用户复验 v25d**：✅ 无残留、四盒一致、模糊质量正常！❌ 但显示的是 Windows 默认蓝色 Bloom 壁纸，
  不是 DesktopSuite 轮换引擎当前设置的壁纸。
- **根因**：`IDesktopWallpaper.GetWallpaper()` 只返回**系统级**静态壁纸设置；DesktopSuite 的
  `WallpaperRotator` 把当前媒体路径存在 `AppSettings.LastMedia`（static/dynamic 两种模式都写这里），
  动态视频走 mpv 渲染器根本不进系统壁纸 API。
- **修复**：`LoadWallpaperFrost()` 改为优先级取壁纸源：
  1. `AppSettings.Load().LastMedia`（DesktopSuite 自身当前壁纸，覆盖静态+动态）→ 优先
  2. `IDesktopWallpaper.GetWallpaper()`（系统壁纸）→ 兜底
  3. 截屏 → 再兜底
  GetPosition 仅在 COM 对象可用时调用，否则默认 DWPOS_FILL。
- 发布 ds2（exe Aug 30 09:50）；git push 因上一轮返回空输出漏推，8/31 补推双远程（d4766b2 已 ls-remote 验证）。

## v25f 毛玻璃（提交 0608877，待真机复验）—— 内部轮换壁纸后自动刷新
- **用户复验 v25e**：① 毛玻璃背景已变 DesktopSuite 当前轮换壁纸（通过）；② 点托盘「立即轮换壁纸」后
  毛玻璃背景**没跟着变（失败）**。
- **根因**：`WallpaperRotator.Tick()` 轮换成功写 `AppSettings.LastMedia` 并 `Save()`，但**未通知 FenceLayer**。
  毛玻璃现有 `WM_FROST_REFRESH` 监听只响应**系统级** `WM_SETTINGCHANGE`（SPI_SETDESKWALLPAPER）；
  DesktopSuite 自身的 mpv 动态/静态轮换走内部 API，**不触发系统事件**，故 `_frostBmp` 缓存不失效。
- **修复（3 处）**：
  1. `WallpaperRotator` 新增 `event Action<string>? WallpaperApplied`，仅在新壁纸实际应用（写入 LastMedia+Save 后）触发；
  2. `FenceLayer` 新增 `public RequestFrostRefresh()` → `PostMessage(_hwnd, WM_FROST_REFRESH)`（复用现有
     拥有者线程刷新链路，线程安全，可从旋转器线程池线程调用）；
  3. `MainWindow` 订阅 `_rotator.WallpaperApplied += _ => _fenceLayer?.RequestFrostRefresh()`。
- **关键**：`LoadWallpaperFrost()` 重新读 `AppSettings.Load().LastMedia`（已落盘），缓存失效后自动取新壁纸，
  无需改取图逻辑。WM_FROST_REFRESH 处理器仅在 Frosted 开启时 `InvalidateFrost()+UpdateVisual()`。
- 发布 ds2（exe Aug 31 09:52），双远程已推（0608877 已 ls-remote 验证 gitee+github 同步）。
- **待用户真机复验**：点托盘「立即轮换壁纸」→ 毛玻璃背景应跟随变化。

## v25g 毛玻璃（提交 2a9914e，待真机复验）—— 修复启动竞态 + 视频壁纸 + 移除截屏
- **用户真机 v25f 反馈**（截图确认）：
  - ✅ 四盒毛玻璃背景一致、显示 DesktopSuite 当前壁纸（绿色调模糊，非 Windows 默认 Bloom 蓝）；
  - ❌ ① 第一次启动时没有自动刷新毛玻璃；
  - ❌ ② 后续轮换壁纸需要过一段时间毛玻璃才跟随切换；
  - ✅ 其余通过。
- **问题 ① 根因**：`MainWindow` 构造函数创建 `WallpaperRotator` → `ChkRotation.IsChecked` 赋值触发
  `ChkRotation_Changed` → `rotator.Start()` → 线程池 `Tick()` 可能**先于** `EnableFences()` 完成。
  此时 `_fenceLayer` 为 null，`WallpaperApplied` 的 `RequestFrostRefresh` 被静默跳过。
- **问题 ② 根因（双因素）**：
  a) `Tick()` 中 `_engine.StartDynamic(file)` 启动 mpv 进程需数秒，`WallpaperApplied` 在此之后才触发；
  b) 若新壁纸是**视频文件**（`.mp4/.mkv`），`Image.FromFile(video)` 抛异常→回落截屏
     （v22-v25c 已证实截屏在 WorkerW 子窗口环境下有 DWM 残留，全系列失败）。
- **修复（3 处）**：
  1. `MainWindow` 新增 `_pendingFrostRefresh` 布尔标记：
     - `WallpaperApplied` 回调中 `_fenceLayer == null` 时设标记（而非丢弃）；
     - `EnableFences()` 创建 FenceLayer 后消费标记，立即 `RequestFrostRefresh()`。
  2. `LoadWallpaperFrost()` 新增视频扩展名检测（`.mp4/.mkv/.mov/.webm/.avi`），
     视频文件提前返回 null 并记录 info 日志（不报错）。
  3. `EnsureFrostCapture()` **彻底移除截屏 fallback**（SW_MINIMIZE/CopyFromScreen/SW_RESTORE）：
     `LoadWallpaperFrost` 返回 null 时 `_frostBmp` 保持 null，
     `DrawBoxes` 走半透明 body 降级分支（`else if (_appearance.Frosted)`），干净无残留。
- 发布 ds2（exe Aug 31 10:12），双远程已推（2a9914e 已 ls-remote 验证 gitee+github 同步）。
- **待用户真机复验**：① 启动后毛玻璃是否自动显示当前壁纸；② 点「立即轮换壁纸」后是否快速跟随。

## M4-B 盒阴影「没有效果」根因定位 + 修复（提交 45458ba，待真机复验）
- **用户两次反馈**：59d19aa（幂曲线+1.6x+默认参数调优）后仍"没有效果"——完全不可见。
- **根因（真机无关，代码层）**：`DrawBoxShadow` 把阴影画在盒子边界**之外**（margin 光晕+右下偏移），
  但 `ApplyRegion()` 用 `SetWindowRgn` 把分层窗口精确裁剪到盒子矩形，阴影像素落在 region 外被 DWM 丢弃。
  所以阴影**从未被合成**——之前 59d19aa 只是把已不可见的阴影调更浓，治标不治本。
- **修复（4 处）**：
  1. 新增 `ShadowRect()` 作为 `DrawBoxShadow` 与 `ApplyRegion` 的单一真值来源（阴影目标矩形）；
  2. `ApplyRegion` 在 `BoxShadowEnabled` 时把每个盒子的阴影矩形并入命中区 → 阴影可见；
  3. `WM_NCHITTEST` 改为：盒子/新建分类瓦片内 → HTCLIENT，阴影光晕内 → HTTRANSPARENT（点击穿透桌面，
     避免不可见阴影吞掉桌面点击）；
  4. `FenceNative` 新增 `HTTRANSPARENT = -1`。
- **沙箱构建失败**：本环境 .NET SDK 损坏（`dotnet --info` 抛 NRE，GetRestoreSettingsTask 报
  "Value cannot be null path1"），无法在沙箱内编译/发布 ds2。已提交 45458ba 并**双远程推送**
  （gitee/github 均 59d19aa..45458ba），需用户在自有机器重新 `publish-ds2.ps1` 构建发布后真机截图复验。
- **未解决/待办**：真机验证盒阴影可见 + 阴影光晕点击穿透是否正常；Route B 其余项（边框色/标题字体/预设）
