## M3.1 真机反馈修复（01:22 用户截图）

### 用户反馈（2 项）
1. **拖拽时原地留残影窗口** — 盒子跟着光标走了，但原位置留一个色块/窗口不消失
2. **条目要图标+名称** — 当前纯文字文件名，想要像资源管理器那样每个条目前面带 shell 图标

### 修复 1：拖拽残影
- **根因**：OnMouseMove 拖拽路径只调 BuildBoxes()+UpdateVisual()，没更新 SetWindowRgn 命中区。而 AlphaFormat=0（恒定不透明）使位图透明区域渲染为不透明黑色 → 旧命中区位置显示黑块 = "原地留窗口"。
- **修法**：OnMouseMove 的 16ms 节流重绘里加 ApplyRegion()，让命中区跟随拖拽的盒子实时更新。
- **改动**：FenceLayer.cs ~608 行，ApplyRegion() 加到 UpdateVisual() 后面。

### 修复 2：Shell 图标 + 名称
- **新增 P/Invoke**：FenceNative.cs 加 SHGetFileInfo + SHFILEINFO 结构 + SHGFI_ICON/SMALLICON 常量。
- **图标缓存**：FenceLayer 加 _iconCache Dictionary<string, Icon> 字段 + GetFileIcon() 辅助方法 + ClearIconCache()。GetFileIcon 用 SHGFI_SMALLICON 取 16×16 图标，Clone 后缓存避免重复 shell 调用；DPI 变化时清缓存。
- **绘制改动**：DrawBoxes 条目循环从 foreach 改为 for（需索引访问 Paths），每行先 DrawIcon 再 DrawString（textX 右移 iconSize+4px）。
- **DLL 大小**：167KB → 168KB（+1KB 图标缓存代码）。

### 发布

- 编译 0 错误 0 警告。

### 环境坑（重申，已验证）

## M3.6 拖拽修复：分类重排重叠 + 条目拖拽幽灵图标（18:01）

### 用户反馈
1. 两个分类交换位置不成功，会重叠到一起
2. 拖动文件图标没有显示拖拽过程，一下子就过去了

### 根因与修复
**问题1 重叠**：`OnMouseMove` 拖拽中持续覆写 `_dragCat.X/Y` 为当前鼠标位置。`EndDrag` 交换时 `cat.X/Y` 已是"压在目标盒上"的坐标 → 交换后两盒同位置 → 重叠。
→ **修复**：新增 `_dragOrigX/_dragOrigY` 字段，在 `OnLButtonDown` Title 分支保存原始坐标。`EndDrag` 交换时用保存值：`cat.X=other.X; other.X=_dragOrigX`（而非互相交换已被覆写的值）。

**问题2 无拖拽过程**：条目拖拽分支只更新目标高亮、不重绘幽灵。
→ **修复**：
- 新增 `_dragItemX/_dragItemY` 字段记录光标位置

- DrawBoxes 末尾新增幽灵绘制：半透明深色底(Argb 120) + 48px 图标 + 名称标签
- 条目绘制循环加跳过判断：正在拖拽的条目不在原盒子中显示
