## 1. 各成员核心结论

### 产品官（产品评审与 MVP 切分）
- **核心判断**：问题不是范围大，是**排序错了**。六块全选 = 没有 Phase 0 = 没有早期正反馈，而个人项目在第 3 个月看不到成果就是死。
- **关键建议**：项目真正价值是「一个 AI prompt 同时产出配色一致的壁纸+小组件+Dock」。能集成的就集成，不能集成的才自研。
- **对主理人的反驳（已采纳）**：AI 的「落点」(theme.json schema) 必须 Phase 0 就定死，只有「实现」排最后。否则 schema 会按"给人改的"设计，到最后发现 LLM 生成不稳定，被迫重构所有模块。**契约放最前，实现放最后。**

### 排障手（技术可行性与选型）
- **核心判断**：Tauri 理论最优，但用户不熟 Rust，**C# 是正确选择** —— Lively 就是 C# WPF 写的，最硬的坑它全踩过且代码可读。两方案架构同构，配置层与 Web 层可无损迁移，沉没成本低。
- **关键建议**：桌面整理**绝不要跨进程操作 SysListView32**（需 `VirtualAllocEx` + `WriteProcessMemory` 写 explorer 内存，是教科书级注入特征）→ 改用「隐藏 DefView + 自绘图标层」，风险归零。
- **情报甄别（重要）**：中文技术站大量文章断言「Win11 24H2 彻底废掉 WorkerW」，经查证含**伪造的性能对比表和虚构的微软工程师发言，属 AI 生成内容农场**。以 Lively 官方 issue #2777 交叉验证，真实结论相反：注入依然可行，但脆弱，需配看门狗。

### 设计师（主题引擎与设计系统）
- **核心判断**：一致性不能靠文档自觉，要靠**机械强制** —— Schema 类型约束（模块层字段类型是 string 而非 number，物理上写不进色值）+ 12 条硬规则 + 校验器六道闸。
- **对主理人的反驳（已采纳）**：AI **不应**输出完整 theme.json（200+ 字段 + 大量需数学推导的派生值，规模和算术两头都会崩）。改三段式：**AI 输出 ThemeIntent（~35 字段、28 枚举）→ 确定性 Expander 展开 → Validator 校验**。
- **实测发现（会直接影响实现）**：**对比度死区** —— 底色 OKLCh 明度 L ∈ [0.58, 0.82] 时，黑白文字都够不到正文门槛，最劣点 L=0.72 上限仅 Lc 55。后果：① 玻璃面板在亮壁纸上会漂进死区，此时**调文字色完全无效，必须回面板层加不透明度**；② 中等明度高饱和品牌色普遍扛不住正文，需提供 `.700` 深档。且死区是**一条带不是阈值**，色阶必须逐档校验。

### 安全卫士（威胁建模与安全需求）
- **核心判断**：最大风险不是被攻击，而是**它自己动了三样不该随便动的东西** —— 用户真实文件、Explorer 窗口树、注册表，任一出错都由用户的机器买单。
- **关键建议（最高优先级）**：桌面整理**锁死为虚拟视图，一个文件都不动**。理由不是误判，而是 **Win11 默认把桌面重定向进 OneDrive，批量移动 = 后端删除+新建，删除会同步到其他设备**。
- **三条架构级要求**：① 全程不提权、无 admin manifest（让"任一 bug 升级为系统级破坏"在结构上不可能）；② 三进程隔离（主程序/壁纸渲染器/小组件宿主），必须在选型阶段定，后期改不动；③ AppBar 默认不注册 —— 失败模式整个消失。
- **WebView2 硬化**：既然只需消费 CSS 变量，**直接 `IsScriptEnabled = false`**，一个开关消灭约九成攻击面。

### 质量门神（打包、测试与回滚）
- **核心判断**：便携版 ZIP，**不做安装包、不买签名证书**。自签名对 SmartScreen **完全无效**（只认证书累积信誉）；真正解法是本地自编译产物无 MOTW，压根不弹。
- **关键技术事实**：**.NET 8/9 官方不支持 WPF 裁剪**（XAML/BAML 靠动态类型解析），强开 `PublishTrimmed` 会得到运行时 `XamlParseException`。减体积的真实杠杆只有压缩 + InvariantGlobalization（省 28MB ICU）。
- **最漂亮的论证**：因为 MVP 锁死「虚拟视图 + `ShowWindow` 隐藏」而非改注册表/移动文件，**最坏情况的破坏全都是非持久化的** —— DefView 的隐藏 explorer 一重启必然恢复。**本架构不存在「重启也回不去」的状态。**
- **交付**：83 条测试用例（8 类）、8 项性能红线、三级还原体系、10 种故障的应急手册。
