描述整个桌面

壁纸、Dock、小组件、桌面整理不是四份平级配置，而是同一组设计 Token 的四个投影。 模块无权定义自己的颜色、圆角与材质 —— 一致性因此不靠约定，靠机制。 AI 只输出 35 个字段的设计意图，剩下的交给确定性编译器。

颜色原语 —— AI 能安全填空的关键

原语形态说明
字面值"#4C8DFF"固定色。也支持 OKLCh 对象形态。
$ref{"$ref":"palette.accent.500","alpha":0.4}引用其它 Token，可覆盖 alpha 或做 OKLCh 偏移。
$derive{"$derive":"wallpaper.vibrant","fallback":"#4C8DFF"}从壁纸提取。支持 dominant / vibrant / muted / averageUnderDock 等，带 clamp 防止壁纸过暗过饱和把 UI 搞崩。
$contrast{"$contrast":{"against":"auto:dock","target":75}}核心原语。引擎保持色相调明度，直到 APCA Lc 达标。against 可写 auto:dock —— 运行时实时采样 Dock 背后的壁纸区域。这让「任意壁纸下文字都可读」成为类型层面的保证，而不是设计时的祈祷。
05

对比度保障 · 三层防御

壁纸可以是任意图片，这是整个设计系统最脆弱的地方。左边是没有保护的样子 —— 白字压在浅色壁纸上， 这就是绝大多数桌面美化方案换张壁纸就崩的原因。右边是三层防御生效后的结果。

第一层｜源头治理：壁纸提示词强制含构图约束（底部 15% 低对比、避免高频细节）。程序化壁纸天然满足，因为色值直接取自 palette。
第二层｜极性自适应：实时采样元素背后壁纸的 OKLCh 平均明度，L > 0.55 切深色前景，L < 0.55 切浅色前景。迟滞 0.06 防止动态壁纸下反复横跳，作用域是 per-element —— Dock 和小组件可以各自处于不同极性。
第三层｜自适应遮罩：仍不达标时按代价从低到高逐级施加：tintOpacity +0.05/步 → 加大模糊 → 注入局部 scrim（≤0.55）→ 文字描边 → 强制极性翻转。 这条链路永不失败，只逐级降级。每次修正写入 meta.generator.repairs，设置界面可展示「本主题自动修正了 3 处可读性问题」。

动态壁纸下的稳定性

措施取值作用
采样降频sampleIntervalMs: 400先降采样到 32×32 再算平均明度，CPU 开销可忽略
迟滞hysteresis: 0.06亮度变化超阈值才响应，防止视频壁纸下遮罩闪烁
过渡插值transitionMs: 600遮罩强度平滑变化，绝不跳变

06

跨模块一致性 · 十二条硬规则

由加载器在渲染前强制校验。违反即拒绝加载或自动修正 —— 不是文档建议，是运行时约束。

#规则强制方式
R1模块层禁止内联字面色值 / 圆角 / 模糊值，只能写 Token key 或 $refSchema 中这些字段类型为 string 而非 number
R2所有面板材质派生自 tokens.material 具名条目，不允许就地定义同上
R3不同圆角值 ≤ 3；且 r(dock) ≥ r(widget) ≥ r(zone) 或三者全等校验器统计后拒绝
R4单光源：所有 elevation 阴影共用同一方向比与阴影色相校验器检查方向一致性
R5所有发丝边取自同一材质 border，颜色随极性自动翻转$contrast 原语求值
R6前景文字对实际背景（含壁纸）APCA Lc ≥ 75 / 60 / 45运行时 adaptiveScrim 保障
R7跨模块同类动作共用同一 duration tokenmotion.energy 单值统一缩放
R8视差系数随 z 层单调递增，最大位移 ≤ 12px校验器钳制
R9所有间距落在 spacing.scale 白名单内（4 的倍数）校验器拒绝白名单外取值
R10最多 2 个字体族 + 1 个等宽；字号取自 typography 阶梯校验器统计
R11面板合成后明度不得落进对比度死区 L ∈ [0.58, 0.82]按最坏壁纸推演，越界则抬 tintOpacity
R12承载文字的填充底色，其承文上限必须 ≥ 该文字角色门槛校验器算 ceiling，不足则要求补 .700 深档
06b

对比度死区 · 实测结论

APCA 实测扫描发现的反直觉约束，直接决定调色板能怎么取值。 「承文上限」= 纯白字与纯黑字在该底色上能达到的 Lc 的较大者 —— 也就是这个底色理论最好的文字对比度。

L 0.52上限 82.7安全
L 0.60上限 72.4死区
L 0.72上限 55.0最劣
L 0.80上限 68.8死区
L 0.84上限 75.4安全

每格上半是底色，上面同时压了纯白与纯黑两种文字 —— 中间三格两种都看不清，这就是死区。 最劣点 L=0.72 上限仅 Lc 55，离正文门槛 75 差得很远。

推论一 · 面板层（R11）

玻璃面板在亮壁纸上合成后会往中间调漂。曜岩玻璃 tintOpacity=0.62 在纯白壁纸下合成为 #6D7177（L=0.54），刚好压在死区下沿外，余量仅 0.04。 若降到 0.50 则合成 L=0.63 落入死区 —— 此时再怎么调文字色都无效，必须回到面板层加不透明度。

tintOpacity 0.62 → 白字 Lc 68.1 tintOpacity 0.70 → 白字 Lc 75.9

推论二 · 调色板层（R12）

中等明度的高饱和品牌色普遍落在死区里：

角色色L上限正文75大字60
#4C8DFF 曜岩 primary0.6664.2✕✓
#FF2E97 霓虹 primary0.6765.6✕✓
#7C9CBF 曜岩 secondary0.6859.9✕✕
#38E1C6 曜岩 accent0.8275.6⚠ 勉强✓
#00F0FF 霓虹 accent0.8784.7✓✓

所以「用 primary 做填充按钮底、上面放正文字号文字」在多数主题里根本不可能达标。 解法不是改文字色，而是填充承文场景改用 primary.700（曜岩 #1C5BC9，上限 85.4）， 或把标签降级为粗体大字（门槛 60）。
另注意死区是一条带而非阈值：accent.600 #00947C（L=0.58）反而又掉回死区， accent.700 #007B65（L=0.50）才重新达标 —— 生成色阶必须逐档校验， 不能假设「越深越安全」。

07

AI 设计接口

需求第 6 条能否落地的关键。核心判断：AI 不应该直接输出完整 theme.json。

✗ 让 AI 直写完整 theme.json

看起来最直接，但不可行：

  • 规模 —— 200+ 字段，字段缺失、枚举越界、括号不闭合的概率高到无法产品化
  • 数学 —— 色阶需在 OKLCh 空间均匀分布，对比度需算 APCA。让概率模型做确定性计算，结果肉眼可见地不均匀
  • 重复 —— 大部分字段是从少数决策机械派生的，逐个填既费 token 又在派生环节引入不一致

✓ AI 输出 ThemeIntent，编译器展开

约 35 字段的设计意图对象：

  • 其中 28 个是枚举，可用受约束解码强制合法
  • 真正自由的只有 3 个 hex 色 + 2 段提示词文本
  • basedOn 必填，把搜索空间从「无限」压到「四个已知良好设计的邻域」
  • 保留 overrides 逃生口（JSON Pointer），但仍须过完整校验管线

职责边界 —— AI 决定"像什么"，引擎决定"是多少"

提示词架构 —— 前三段固定可缓存

┌─ Block 1  系统契约（固定，可缓存）
│  • 角色：桌面主题设计师
│  • ThemeIntent Schema 精简版（枚举值全列出）
│  • 硬要求：只输出纯 JSON，无 markdown 围栏，无解释文字
│  • basedOn 必填，必须从 4 个锚点中选
│
├─ Block 2  设计法则（固定，可缓存）
│  • 暗色主题 surface 明度 L ∈ [0.10, 0.22]；浅色 L ∈ [0.92, 1.0]
│  • accent 与 primary 色相差 Δh ≥ 60° 或 = 0°（同色系）
│    └ 避开 20°~50° 脏区间 —— 那是配色显廉价的主因
│  • 强调色全屏面积 < 5%
│  • 中性色必须带 primary 微量色偏（C ≈ 0.01~0.02），纯灰显脏
│  • 材质 + 形状 + 动效必须同性格：玻璃配圆角配弹性，
│    平面配锐角配线性。混搭是 AI 生成主题最典型的失败模式
│  • 壁纸提示词必须含构图约束：底部 15% 低对比、避免高频细节
│
├─ Block 3  Few-shot（固定，可缓存）
│  • 3 组「用户描述 → ThemeIntent JSON」样例
│  • 取自预置主题，覆盖 暗玻璃 / 浅极简 / 高饱和 三个方向
│
└─ Block 4  用户输入（变化）
   • 用户一句话
   • 可选上下文：当前壁纸取色摘要 · 屏幕分辨率 · 已装字体 · 历史偏好

校验与兜底 · 六道闸

G1
语法闸

JSON 解析与自动修复：剥 markdown 围栏、补引号、去尾逗号。失败则重试。

G2
Schema 闸

缺失字段从 basedOn 预置主题继承 · 未知字段丢弃并记录 · 枚举越界取最近合法值。

G3
范围闸

数值钳制：blur ∈ [0,64] · iconSize ∈ [24,96] · opacity ∈ [0,1] · duration ∈ [60,2000] · magnifyScale ∈ [1,2.5] · widgets ≤ 8。

G4
对比度闸 · 核心

对全部前景/背景组合算 APCA。不达标时五步降级：① 保色相调明度（±0.02，24 步）② 降色度重试 ③ 提高 tintOpacity（≤+0.3）④ 注入 scrim（≤0.55）⑤ 强制极性翻转。五步内必然收敛，永不失败。

G5
和谐闸

色相脏区检测（Δh ∈ [20°,50°] 且双方 C > 0.1 → 把 accent 推到 Δh=60° 或归零）· 暗色 surface 色度 C ≤ 0.04 · 高饱和色覆盖 ≤ 12% 面积 · 圆角种类 ≤ 3 · 字体族 ≤ 2。

G6
性能闸

模糊预算 Σ(面板面积 × blurRadius) ≤ B · 视频 ≤ 1 路 4K30 或 2 路 1080p30 · WebView 小组件 ≤ 3。超预算按固定顺序降级：ambientAnimation 关 → parallax 关 → blur 减半 → shader quality 降级 → fps 30→20。

重试策略：校验失败把具体错误回灌给模型重试，最多 2 次。仍失败则回退到 basedOn 指向的预置主题，只应用能解析出的颜色偏好。永不向用户报错。 所有自动修正记入 meta.generator.repairs，既保证可用，又保持透明。
