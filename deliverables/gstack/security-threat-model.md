# Windows 桌面美化套件 — 实施前威胁建模与安全需求规格

> **文档定性 / 免责声明**
>
> 本文是**实施前的威胁建模与安全需求规格书**，不是代码审计结论。
>
> 截至本文撰写时，项目仓库为空：无源码、无 lockfile、无 CI 配置。因此本文中的所有"风险"均为**基于技术方案的预判**，来源于对候选实现路径（WorkerW 注入、注册表写入、AppBar、WebView2、AI 集成）的经验判断，**没有任何一条经过实际复现验证**。
>
> 本文**不构成"代码是干净的"的证据**。代码写出来之后必须重新做一次真正的审计。
>
> 评判标准为**个人自用**：只关心"什么会把用户自己的机器搞坏、把文件搞丢、把 Key 泄露、引入恶意代码"，不含任何企业合规内容。

---

## 一、结论先行

这个项目的风险不是"被黑客攻击"，而是**自己把自己的机器搞坏**。攻击者是谁不重要，重要的是：你写的代码会去动 Explorer、动注册表、动用户真实文件，而个人项目通常因为"反正自己用"跳过一切防护。

三个最高优先级判断：

1. **桌面整理必须做成虚拟视图，不移动真实文件。** 这是全项目唯一能造成不可逆损失的功能，虚拟视图能把该风险直接降到零。
2. **全程不提权。** 不要 admin manifest。MVP 四块功能（HKCU 注册表、用户桌面目录、WorkerW SetParent、AppBar、WebView2）全部不需要管理员权限。需要提权的功能一律砍掉——这一条控制的收益超过后面所有校验逻辑之和。
3. **崩溃可恢复优先于功能完整。** 桌面壳层软件的可靠性定义不是"不出错"，而是"出错之后用户还能用电脑"。

---

## 二、七个高危点

### 1. WorkerW 注入的爆炸半径与恢复

技术路径是向 Progman 发未文档化消息 `0x052C` 让其生成 WorkerW，再 `SetParent` 把渲染窗口挂进去。三个真实风险：

**杀软误报**：`FindWindowEx` 定位其他进程窗口 + `SetParent` 跨进程挂载 + 常驻后台 + 开机自启，这组行为特征与恶意软件高度重合。叠加未签名 EXE，SmartScreen 必拦，国内 360/火绒大概率报毒。个人项目买签名证书不现实，所以**不要试图消除误报，而要让误报不致命**：注入失败必须是可降级的（回落到静态壁纸），绝不能因此启动失败或崩溃。

**Explorer 重启导致黑屏**：Explorer 崩溃、用户手动重启它、Windows 更新，都会销毁 WorkerW，我们的窗口就成了孤儿，桌面变黑或图标不重绘。**这是必然会发生的，不是异常路径。** 必须用 `RegisterWindowMessage("TaskbarCreated")` 注册广播消息——Explorer 重启时会广播它——收到后重新走一遍挂载流程。再叠加一个 `IsWindow()` 轮询看门狗兜底。

**架构约束**：被 `SetParent` 的必须是一个**专用的、可抛弃的渲染窗口**，绝不能是主 UI 窗口；且渲染器应当是**独立子进程**。这样孤儿化/GPU 挂死只损失渲染层，主程序活着，可以杀掉重建。退出时必须 `SetParent(hWnd, NULL)` 再销毁，并触发一次桌面重绘。另外提供 `--safe` 启动参数和一个全局热键，一键拆除所有注入。

### 2. 注册表写入与回滚纪律

**唯一有效的架构控制**：所有注册表写入收敛到一个封装函数，函数内硬编码一张**键路径白名单**，白名单外的路径直接抛异常。这让"写错键"这一整类 bug 在结构上不可能发生。

写入前必须落盘一份 JSON 日志，记录 `{键路径, 值名, 原类型, 原数据, existed: bool}`。`existed: false` 是关键——还原时应该是**删除**该值，而不是写个空值。卸载时倒序重放日志。

### 3. AppBar 工作区残留

`SHAppBarMessage(ABM_NEW)` 预留了屏幕边缘区域，若进程被任务管理器强杀 / 崩溃 / 断电，`ABM_REMOVE` 不会执行，预留区残留，最大化窗口永久躲开一条，直到 Explorer 重启。

**最好的对策是不注册 AppBar。** 默认把 Dock 做成普通置顶窗口 + 自动隐藏，不预留任何空间，这个失败模式就整个消失了。"预留屏幕空间"降级为高级选项、用户显式开启。

若确实开启：`ABM_NEW` **之前**先把"已注册"标志和原始工作区矩形写盘并 flush；下次启动发现标志还在（说明上次没干净退出）就调 `SystemParametersInfo(SPI_SETWORKAREA)` 还原。同时提供 `--repair` 参数和菜单项手动重置工作区。`WM_DISPLAYCHANGE` / DPI 变化时必须重算——分辨率变了而 AppBar 矩形是旧的，就是"屏幕永久缺一块"的经典成因。

### 4. 桌面整理：移动真实文件 vs 虚拟视图 —— **推荐虚拟视图**

**明确推荐：MVP 只做虚拟视图，一个文件都不动。**

移动真实文件会撞上一串问题：快捷方式失效、安装程序反复重建图标、软件硬编码桌面路径、Explorer 的图标位置缓存被打乱且不可逆。而**最危险的是同步盘**：Win11 默认把桌面重定向进 OneDrive，在同步目录里批量移动 = 后端的删除+新建，可能把删除同步到其他设备，还会引发版本冲突。这是本项目最可能真正弄丢用户文件的路径。

虚拟视图方案：我们的覆盖层渲染一个分组、过滤后的桌面视图，文件从不移动；"隐藏"= 我们不画它；卸载 = 文件从未被碰过，无需还原。**不可逆数据损失风险归零。**

配套需要隐藏真实图标（否则两层重叠），做法是向 `SHELLDLL_DefView` 发 `WM_COMMAND 0x7402`（等价于右键菜单"显示桌面图标"），单一开关、瞬时可逆、非破坏性。

"隐藏"三种实现的安全排序：**渲染层不画 > 设置隐藏属性 > 移动文件**。中间那个虽然可逆，但它把状态泄漏到我们程序之外——程序挂了用户就面对一堆看不见的文件且不知道为什么，不推荐。

### 5. API Key 存储

绝不硬编码进 EXE（`strings` / dnSpy 秒破），绝不明文存配置文件。

**推荐：Windows 凭据管理器为主，DPAPI（`ProtectedData.Protect` + `CurrentUser`）为备。** 两者底层都绑定当前 Windows 账户，同机其他用户读不到；凭据管理器的额外好处是用户能在系统 UI 里看见并自行撤销。**环境变量不推荐做持久存储**：持久环境变量明文存在 `HKCU\Environment`，任何进程可读，还会泄漏进子进程和崩溃转储，仅可作为开发期覆盖。

配套：Key 绝不进日志、绝不进 URL query（只走 Authorization 头）、错误信息中脱敏、卸载时删除凭据。

### 6. AI 输出作为不可信输入

**把 AI 生成的 theme.json 完全等同于陌生人发来的文件。** 最强的缓解不是校验逻辑，而是**收窄 AI 的输出能力**：让 AI 只产出受约束的颜色/数值 JSON（色值、圆角、间距、透明度），**不产出任何 HTML/CSS/脚本**。这一步就消灭了整个注入类问题。

其余校验见下表。另外必须有**自动回滚**：任何 AI 主题应用后启动 10 秒倒计时，用户不确认就自动还原——主题把桌面变得不可读时，这是唯一的出路，且实现成本极低。

**隐私出口**："AI 帮我整理桌面"要把文件列表发出去，而文件名泄漏量极大（`离婚协议.docx`、`简历_投递XX.pdf`、客户名、项目代号）。要求：只发文件名不发完整路径；发送前把**完整载荷原文**展示给用户确认；提供"只发扩展名和数量"的降级模式（`{.docx: 12, .png: 30}`，对整理建议已经够用）；绝不发送文件内容；绝不开机自动发送。

### 7. 第三方主题包沙箱化

一旦壁纸支持网页/Shader、小组件支持脚本，安装一个包就等于运行陌生人的代码——Rainmeter 的 `!Execute` 能拉起任意进程，Wallpaper Engine 的网页壁纸是完整 CEF，两家都真实踩过。

核心架构要求：**壁纸渲染器和小组件宿主各自跑独立子进程**，崩溃/挂死/GPU 故障被隔离，可杀可重建。具体沙箱配置见第三节和分级清单。

包解压时**Zip-Slip 是头号 bug**：必须对每个条目的规范化目标路径做"是否仍在解压根目录内"的校验后再落盘，拒绝绝对路径、`..`、符号链接条目，并限制解压总大小与条目数（zip bomb）。包内文件扩展名走白名单，`.exe/.dll/.ps1/.bat/.cmd/.vbs/.scr/.lnk/.msi` 一律拒绝——主题包没有任何正当理由包含它们。**安装时绝不执行任何东西**，不支持安装钩子。

## 三、对产品评审三条建议的安全表态

| 产品建议 | 安全表态 | 理由 |
|---|---|---|
| 动态壁纸集成 Lively，不自研 | **✅ 净加分，但要限定集成方式** | 加分：WorkerW 注入的兼容性地狱（22H2/24H2 各版本差异、Explorer 重启恢复）由一个成熟项目承担；崩溃爆炸半径移出我们进程；Store 版本经过微软签名与分发，杀软误报风险大幅低于我们自己的未签名 EXE。新增信任问题：①供应链——**不要捆绑分发它的二进制**，改为检测本机已安装 / 引导用户自行从 Store 安装，既避免我们为其完整性背书，也规避 GPL 系许可证的传染性（**集成前请复核其具体许可证**）；②它的网页壁纸同样是在跑第三方代码，这部分风险我们继承但不可控，需在 UI 上如实告知用户；③其命令行/IPC 控制接口通常无认证，同机任意进程可驱动——个人自用可接受，需知悉。 |
| 小组件降级为 HTML + 消费 theme.json 的 CSS 变量，WebView2 渲染，无插件 API | **✅ 方向正确，但默认配置不够，必须显式加固** | WebView2 是 Chromium，自带渲染器沙箱和同源策略，起点远好于进程内嵌脚本引擎。但危险的不是渲染器逃逸，而是**我们主动递给它的能力**。若小组件真的只需 CSS 变量，则**直接 `IsScriptEnabled = false`**——这一个开关消灭约九成攻击面，是本方案能否称为"沙箱"的分水岭。JS 应为逐组件、用户显式授权后才开启。完整加固项见分级清单 🔴 段。 |
| 砍掉系统主题改造，只用官方 API，不碰 SecureUxTheme / ExplorerPatcher | **✅ 强烈确认，坚决砍掉** | 失败模式是**灾难性且难恢复**：这类方案依赖逐版本的未文档化偏移或绕过签名校验，Windows 累积更新改了偏移 → explorer.exe 登录即崩溃循环 → 用户没有桌面、没有任务栏，只能进安全模式救。ExplorerPatcher 在 Win11 多次更新中反复出现过这种情况。这不是"功能坏了"，是"机器不能用了"。且绕过签名校验本身就是恶意软件行为，杀软必报；通常还需管理员权限，会把全项目的爆炸半径抬高一个数量级。对个人折腾项目，为了第三方 msstyles 承担锁死登录会话的风险，性价比极差。官方 API（亮暗模式、强调色、壁纸、指针）+ 我们自己的 Dock/小组件层已经能承载绝大部分视觉个性，视觉识别度本来就主要来自后者。用户若坚持要 msstyles，正确做法是"文档里写明这是用户自担风险的手动外部步骤"，而不是"我们的 EXE 替他做"。 |

## 四、分级安全清单

### 🔴 必须做（不做就别写这个功能）

| # | 要求 | 关联功能 |
|---|---|---|
| R1 | **全程不提权**，无 admin manifest；需要管理员权限的功能一律砍掉 | 全局 |
| R2 | 桌面整理 MVP **只做虚拟视图，不移动/不重命名/不删除任何真实文件** | 桌面整理 |
| R3 | **任何情况下不删除用户文件**，不调回收站，不做"清理" | 桌面整理 |
| R4 | 注册表写入收敛到单一封装 + 硬编码键路径白名单，白名单外抛异常 | 主题/自启 |
| R5 | 注册表写入前落盘 `{键,值名,原类型,原数据,existed}` 日志，卸载倒序重放 | 主题/自启 |
| R6 | 注册 `TaskbarCreated` 广播消息，Explorer 重启后自动重新挂载 WorkerW | 壁纸 |
| R7 | 被 SetParent 的是专用可抛弃渲染窗口，且渲染器为**独立子进程**；注入失败可降级为静态壁纸，不得导致启动失败 | 壁纸 |
| R8 | 退出时 `SetParent(NULL)` + 销毁 + 触发桌面重绘；提供 `--safe` 与全局热键一键拆除 | 壁纸 |
| R9 | Dock **默认不注册 AppBar**（置顶窗口 + 自动隐藏）；预留工作区为显式高级选项 | Dock |
| R10 | 若启用 AppBar：注册前先落盘标志与原始工作区；启动时检测残留并 `SPI_SETWORKAREA` 还原；提供 `--repair` | Dock |
| R11 | API Key 存凭据管理器或 DPAPI；**绝不硬编码、绝不明文落盘、绝不进日志/URL** | AI |
| R12 | AI 只允许输出**受约束的颜色/数值 JSON**，不得输出 HTML/CSS/脚本 | AI |
| R13 | 主题配置严格 schema 解析，未知字段**拒绝**而非忽略；禁用多态/类型名反序列化（如 Json.NET 的 `TypeNameHandling`） | AI/主题包 |
| R14 | 所有资源路径必须相对、规范化后仍在包根目录内；拒绝绝对路径、`..`、UNC（`\\host\share` 可致 NTLM 哈希外泄）、`file://`、`\\?\`、盘符相对路径、设备名、重解析点 | AI/主题包 |
| R15 | 所有数值强制钳位（透明度 0–1、模糊半径 0–64、字号 8–72、FPS ≤60、图标 16–256、组件数上限）；拒绝负数/NaN/Infinity | AI/主题包 |
| R16 | 应用任何 AI 主题走"备份 → 应用 → 10 秒未确认自动回滚" | AI |
| R17 | 向 AI 发送桌面文件列表前，**完整载荷原文**展示给用户确认；只发文件名不发路径；绝不发文件内容；绝不开机自动发送 | AI |
| R18 | WebView2：`IsScriptEnabled=false`（除非用户逐组件授权）、`AreHostObjectsAllowed=false`（永不 `AddHostObjectToScript`）、`IsWebMessageEnabled=false`、`AreDevToolsEnabled=false`（release） | 小组件 |
| R19 | WebView2：经 `SetVirtualHostNameToFolderMapping(..., DenyCors)` 加载，**绝不用 `file://`**；`NavigationStarting` 取消一切非本包 URI；`NewWindowRequested` 一律取消 | 小组件 |
| R20 | WebView2：默认**阻断一切网络出站**（`AddWebResourceRequestedFilter` + 取消非虚拟主机请求）；出站按组件、按域名、用户逐条授权 | 小组件 |
| R21 | **绝不传 `--no-sandbox` / `--disable-web-security`** 给 WebView2 | 小组件 |
| R22 | 解压主题包必须做 Zip-Slip 校验（规范化后仍在解压根内）；拒绝绝对路径/`..`/符号链接条目；限制解压总大小与条目数 | 主题包 |
| R23 | 包内扩展名白名单；`.exe/.dll/.ps1/.bat/.cmd/.vbs/.scr/.lnk/.msi` 一律拒绝；安装时不执行任何内容 | 主题包 |
| R24 | 卸载必须完整还原：重放注册表日志、移除自启项、还原工作区、删除凭据 | 全局 |

## 五、红线清单（绝对不做）

| # | 禁止的操作 | 后果 |
|---|---|---|
| X1 | 任何形式的**静默删除**用户文件 | 不可逆数据损失 |
| X2 | 对**桌面目录之外**的任何路径做整理/隐藏/移动 | 越界破坏 |
| X3 | **递归**处理子目录 | 爆炸半径失控 |
| X4 | 移动时**覆盖同名文件**（`overwrite: true`） | 静默数据损失 |
| X5 | 写 **HKLM** 任何位置 | 影响全机与其他用户 |
| X6 | 碰 `Winlogon\Shell` / `Userinit` | 改错即无法登录 |
| X7 | 碰 `Image File Execution Options` / `AppInit_DLLs` | 恶意软件技法，杀软必报 |
| X8 | 碰 `HKCR` / 文件关联 | 破坏系统可用性 |
| X9 | 碰 `Session Manager` 等启动关键键 | 可致系统无法引导 |

## 七、「桌面整理」安全实现约束

这是全项目唯一能造成不可逆损失的模块，因此写到可直接照做的程度。

### 7.1 MVP：虚拟视图（唯一推荐路径）

```
扫描  = 枚举 %USERPROFILE%\Desktop 与 %PUBLIC%\Desktop 的【直接子项】
        （只读枚举，不打开、不修改、不加锁）
分组  = 纯内存计算，按扩展名/时间/自定义规则
隐藏  = 该项不加入渲染列表。仅此而已。
落盘  = 只写我们自己的 config.json（记录分组规则与隐藏项的文件名）
真实文件系统写操作次数 = 0
```

真实桌面图标的隐藏：向 `SHELLDLL_DefView` 发 `WM_COMMAND 0x7402`（等价于右键菜单"显示桌面图标"），单开关、瞬时可逆、非破坏。程序退出/崩溃后用户右键即可自行恢复。

卸载：删掉我们的 config 即可，**没有任何东西需要还原**。

### 7.2 若未来确实要做真实移动（Phase 2，默认关闭，需用户显式开启）

| 约束 | 具体要求 |
|---|---|
| 作用域锁 | 仅两个 Desktop 目录的**直接子项**。每个路径 `GetFullPath` 规范化 + 解析重解析点后，校验其父目录严格等于桌面根；不等则拒绝。这条同时封死 junction/符号链接逃逸 |
| 不递归 | 遇到子目录只作为整体移动，绝不进入其内部 |
| 目标位置 | 只能是桌面内的应用自有目录（如 `Desktop\_整理\文档\`）。**同卷** → 移动是原子的，无复制+删除；**同步范围内** → 避免跨边界的同步删除语义 |
| 禁止覆盖 | 重名一律自动加后缀，**永不** `overwrite: true` |
| 禁止删除 | 不删除、不进回收站、不清理。无例外 |
| 干跑强制 | 先展示完整计划（共 N 项，逐条 源 → 目标），用户显式确认后才执行。**禁止开机自动整理** |
| 批量上限 | 单次 ≤200 项，超出则拒绝并要求用户缩小范围 |
| 撤销日志 | **第一次移动之前**就把 JSONL 写盘并 flush：`{opId, ts, src, dst, size, mtime}`。撤销倒序重放。日志必须跨重启可用，不能只在内存 |
| 同步盘预检 | 检测桌面是否位于 OneDrive/坚果云/Dropbox 下（重解析点 / 已知文件夹重定向 / 进程名）。是 → **默认拒绝真实移动模式**并强提示 |
| 跳过项 | `desktop.ini`、带 SYSTEM 属性的项、当前被占用的文件（先尝试独占打开探测，失败即跳过，**不重试不强制**） |
| 失败处理 | 任一项失败即停止整批，不继续；已完成部分保留在撤销日志中可回退 |
| 卸载 | 必须先提供"全部还原到原位置"，执行完才允许删除撤销日志；**永不删除 `_整理` 目录** |

## 八、一句话安全结论

**这个项目最大的安全风险不是被人攻击，而是它自己动了三样不该随便动的东西——用户的真实文件、Explorer 的窗口树、以及注册表——任何一处出错都由用户的机器买单；必须守住的底线是四条：桌面整理只做虚拟视图绝不移动真实文件、全程不提权、注入与 AppBar 失败后能自动恢复不留残骸、AI 与第三方主题包的输出一律当作不可信输入且永不作为代码执行。**
